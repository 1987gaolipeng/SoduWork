# SoduWork 管理端

**简体中文** · [English](README.md) · [开发指南](../docs/development.md#管理页面)

命令示例中的 `sh start.sh` 适用于 macOS/Linux；Windows PowerShell 使用 `.\start.cmd`，命令提示符使用 `start.cmd`，参数相同。独立 Python 工具示例使用 `python3`；Windows 使用 `py`，已激活虚拟环境时使用 `python`。

React + Vite 应用，对接 `../hub-backend` 的管理 API。当前入口为 `src/main.jsx`，路由与页面在 `src/` 维护；设计原型不参与应用运行。

项目、登记仓库、部门和职业画像默认显示业务数据。新记录会继承创建账号或所属记录的测试标识。升级后，可按关键词查找历史未分类数据，每次最多勾选 200 条，核对名称后标记来源或归档。已归档的数据可以在归档视图中恢复。新建用户时，只能选择所属部门可用的正式或未分类职业画像。

## 职责

管理组织与账号、客户端与执行网络、模型与能力、任务与审批、插件和发布配置。权限由 Hub 校验，前端隐藏按钮不能替代接口权限检查。

复制管理页面的地址即可分享或在新标签页打开。例如，具备相应权限的账号可用 `/#/identity` 直达「身份接入」。浏览器的后退和前进按钮可返回已浏览的页面。「用户管理」刷新后会在当前标签页恢复该管理员的搜索和部门筛选。通过复制的链接打开时，筛选条件为空。

模型目录默认显示服务、模型数量与实时负载的紧凑摘要；展开概览可查看配置、近一小时统计和请求分布，收起时仍可操作服务和并发设置。服务按启用优先排序，同一启停状态内自定义服务优先。新建服务当次会移到前面便于定位，重新进入后恢复上述稳定分组顺序。

删除自定义模型服务前，请核对将删除的模型，以及可见范围内选用同名共享模型的成员和未完成需求。部分选择仅记录模型名称，因此可能对应多个服务。输入完整的服务 ID 后才能删除；清单发生变化时需要重新确认。

服务卡片根据内容区宽度自适应为一至四列；点击“查看”打开模型详情弹窗，服务网格的大小和位置保持不变。添加模型、发现模型和配置服务保持可见；启停与删除收进“更多”浮层，删除继续保留原有确认。

## 界面语言

界面先使用已保存的语言，其次采用浏览器偏好中的第一个受支持语言，最后回退到英文。繁体中文偏好目前使用简体中文，仅当该偏好实际造成回退时显示提示。选择任何受支持语言，包括当前显示的简体中文，都会保存明确选择并清除提示；重新加载后继续尊重这一选择。读取已有配置时不会改写其中的语言标签或其他设置。

## 处理待审请求和失败流程

在运行监控点「等待人审」，可查看权限范围内的待审请求和等待时长。有相应查看权限的人还可以看到需求、版本和仍待投票的处理人。请求到达截止时间后显示超时提醒，未设置截止时间的请求在等待 24 小时后提醒。被指派的处理人凭对应关卡的审批权限即可投票，也可以按审批策略转交自己的待办。具备审批权限的请求发起人、需求创建人可以撤回待审请求。超级管理员可以管理撤回和转交。撤回会停止关联关卡，继续执行前需重新发起审批。交付成果始终由需求创建人验收。

在「最近失败」打开对应需求或失败节点的运行日志。解决原因后，有运行权限的人可以重试符合条件的节点。使用共享模型网关的 AI 节点可以改用组织内其他可用模型重试，原来的执行记录保留在运行历史中。

## 设置首次对话

有集成管理权限的管理员可以在治理总览查看**首次对话清单**。先连接模型服务，再选中该服务添加或发现对话模型。最后两步分别打开桌面端的底座和模型设置。用同一账号登录桌面端后，这里会显示该账号的检测结果。点击**重新检测**可刷新进度。**跳过清单**会在本浏览器为当前账号收起清单，点击**查看首次对话清单**即可恢复。

## 核对 Skill 开放策略

能力目录按界面语言显示内置 Skill 的用途摘要，展开后可以查看作者原文。用卡片上的开关修改草稿，再点**保存开放策略**查看将要新增、移除的 Skill。系统根据已激活终端的 Skill 选择和所属员工的部门估算影响范围，同一台终端即使涉及多项变更也只计一次。确认后新策略在员工下次执行时生效，取消可返回草稿继续修改。

## 排查用量与成本

在**用量与成本**页打开异常明细，可查看原始记录 ID 和精确到个位的 Token 数，包括最近 30 条以外的记录。单条日账本记录超过 10 亿 Tokens 时会被标记。排除这些记录后，可以比较其余用量的趋势和场景分布。

打开未计价明细可以核对涉及的模型。输入适用的供应商最高单价（美元／百万 Tokens），可估算这部分用量的费用。再填入所选期间的美元预算，即可看到已计价美元金额与估算费用合计占预算的比例。试算仅在当前页面生效。

## 自动化模板生效日期

模板默认选择**长期有效**。取消勾选后，可以指定开始日期、结束日期或两者。日期按模板时区计算（默认为 Asia/Shanghai），包含开始日和结束日；区间内的执行时间由已有的每小时、每天或每周节奏决定。保存前会校验日期是否合法、开始日期是否晚于结束日期。

桌面端将这些默认值填入新自动化，用户创建前仍可修改。修改模板不会更新已经创建的自动化。结束日期后不再安排新的周期触发或失败重试；最后一个有效触发时刻保留调度器原有的一轮轮询宽限。已执行的任务和记录保留。需要恢复后续运行时，修改自动化自身的日期范围；需要让后续用户使用延期范围时，另外修改模板。模板仍可使用，直到管理员主动停用。

## 开发运行

先起后端（另一个终端）：
```bash
cd ../hub-backend
.venv/Scripts/python -m uvicorn app.main:app --port 9080
```
再起前端：
```bash
npm ci             # 按锁文件安装
npm run dev        # http://localhost:5173
```
Vite 将 `/api`、`/healthz` 和 `/readyz` 代理到 `127.0.0.1:9080`（见 `vite.config.js`）。如果配合根目录 `sh start.sh` 使用，先通过 `SODUWORK_DEV_HUB` 将代理指向 `http://127.0.0.1:18989`，具体命令见[开发指南](../docs/development.md#管理页面)。登录使用 Hub 的用户账号；首次初始化管理员由 Hub 的 `ADMIN_USER` / `ADMIN_PASS` 配置产生，后续通过用户管理维护，不是前端写死账号。

## 验证与构建
```bash
node --test tests/*.test.mjs
npm run build      # dist/ 为生成物，由 Hub 或部署环境托管
```

浏览器场景见 `tests/` 中的独立运行脚本；真实环境测试与隔离页面夹具应分别记录。`dist/`、依赖和本地配置不提交到 Git。

构建后运行 `node tests/run-model-catalog-layout-browser.cjs /absolute/evidence/directory`，检查模型目录的四语言布局、折叠、轮询及重新加载排序。需安装客户端 Electron 依赖，或通过 `SODUWORK_ADMIN_TEST_ELECTRON` 指定其可执行文件。场景使用本地合成响应，不连接真实 Hub 或模型服务。
