# 需求交付完成修复计划

[English](2026-11-18-requirement-delivery.md)

目标：本机会话执行完毕后进入待验收、明确的手动提交或可处理的交付异常，避免静默停在执行中。

架构保持 Hub 决定验收状态，复用按账号隔离的持久化回执队列、固定交付内容和创建人验收规则。将用户提交选择与实际提交方式分开保存，自动判断只采用本轮校验通过的正式成果。

实施顺序：

1. 后端先补默认策略、显式手动、旧版手动、无效文件及重复请求的失败用例，再实现独立的提交选择字段与交付时判断。
2. 本机准备请求传递并核实该选择，后续轮次和旧数据保留原策略。
3. 文件识别先补 JSON 成果及配置文件排除测试，再修复识别规则。
4. 核查完成至回执落盘之间的异常窗口，补重启与补发测试，只修复证实的缺口，不通过超时推断完成，不重新执行模型。
5. 界面根据权威回执呈现待同步、待提交和具体异常，复用现有操作入口；验收人缺失时保留权限边界。
6. 运行组件测试、隔离的 Pi SDK 与 Hub 模拟，以及公开源文件、第三方、文档和敏感信息检查。保留其他未提交改动。

验收覆盖 MD/JSON、中文与分解 Unicode 文件名、默认及手动策略、命令失败后正常完成、断网、响应丢失、重启、重复交付、账号隔离和验收人缺失。没有实机运行的 macOS/Linux 验证如实标记。不会新增调度系统、全目录上传、自动批准验收或批量改变历史手动选择。

## 验证记录

已在 Windows 上使用合成账号和一次性数据验证。最终定向客户端测试通过 294 项，界面及本地化测试通过 192 项。后端分别通过 56 项生命周期及交付测试，以及 31 项最终策略和创建人恢复测试。本机 SDK 与模拟 Hub 的 Markdown、JSON 矩阵，以及三个隔离 Electron 验收套件均通过断言。完整 `npm test` 运行了 9,936 项测试，其中 9,925 项通过、9 项跳过，另有两项断言因加载期间发生并发界面修改而失败；这两项均已包含在最终通过的定向测试中。上述修改后尚未重新运行完整套件。公开源码、文档、第三方和秘密扫描检查通过。未实机验证原生 macOS/Linux 或生产模型。

提交前复核补充了明确文件交付约定下只有旧成果且本轮无变化的回归测试，并修复了空采集路径。随后完整客户端测试通过 9,928 项，零失败，9 项按平台或环境条件跳过。后端交付与 Runner 事件组合测试全部通过，共 129 项。启动器测试通过，5 项按平台条件跳过；使用隔离配置的真实 Electron 诊断检查通过。

后端 release 的 403 项检查通过四个原生分片全部完成。同步 release 提交 `11fa69f2` 后，625 项客户端组合回归及隔离 Electron 的退回修改交付流程通过。完整客户端套件在同步前运行；同步后的组合回归覆盖本地修改和上游新增修改的客户端测试文件。公开源码、目录结构、第三方、文档及秘密扫描再次通过。严格本地化审计与同步后的 release 基线一致，仍有 437 项界面缺失及 695 项待复核条目，没有新增缺失文案；这些既有审计缺口尚未消除。
