# 五类即用

先选类型；UI、技能、数据、入口、验收随类型变化。共同规则见 host-sdk.md 与 design-quality.md。

| 类型 | 制作重点 | 数据 / AI / 后台 | 必测 |
| --- | --- | --- | --- |
| 工具办公 | 一句意图→结果；精简编辑、空态、撤销 | 本机 data；AI 起草/归类/整理，确定性动作直接执行，结构化结果校验后落库 | 真实输入→处理→保存→重开；并发冲突 |
| 小游戏 | 题材美术；画布/动效/声音；暂停、重开、键盘/触控；先玩法再装饰 | 实时游戏循环不等模型；宿主只存进度/成绩；AI 按需生成关卡 | 首局、输赢、暂停、重开、窄屏、性能；单个题材彩色图标 |
| 机器人 | 配置→手动试跑→订阅→运行记录/结果；窗口只展示和管理 | 明确业务订阅入口（内部 automation）＋宿主 MCP＋数据；计划走 Hub/Runner；幂等、失败可重试；无窗口执行 | 真实计划→执行→结果落库→关窗→再执行→重开查看；失败/设备离线如实呈现 |
| 其他 | 先定义一个清晰场景与完成动作；按内容选择卡片/画布/列表 | 数据按真实需要；需要 AI 或持续任务才接对应宿主能力 | 核心动作闭环；不堆空按钮和通用仪表盘 |
| WEB/H5 接入 | 已有网站/H5：复用真实入口、登录与设置；云端服务：制作可操作前端并对接真实 API | 同源桥、明确鉴权/参数/MCP；在线业务数据归实际服务；需要本机数据可接宿主；不要求业务空间 ID，除非真实服务需要 | 真 URL、登录/失效、设置、实际业务请求、AI 工具、重开；不能用假接口或仅 iframe 宣称完成 |

机器人创意：灵感扭蛋机、脑洞辩论员、下班收尾官、会议行动员、项目哨兵。角色设定与输出遵守 [robot-persona.md](robot-persona.md)；必须有真实职责、触发、执行、持久结果和回看。

机器人最小闭环：输入集合 → 声明 automation:true 与 soduwork-jiyong → 创建现有计划 → 手动运行核验 → 按真实 revision 写结果集合 → 页面刷新读取。记录 runId/时间/输入摘要，避免同次重复写；默认不改源记录。用户未授权订阅时不自动建长期计划；测试不能把 fixture 当真实调度或模型验收。
