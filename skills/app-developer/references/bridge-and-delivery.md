# SoduWork 即用开发

这是插件开发能力的扩展，沿用同一包格式、会话工具、授权和交付链路。先读本轮资源中的 `plugin-development.md`（插件开发助手的同源规范），再按下面的即用要求实施。普通插件仍使用 method、connector 或 workflow。

## 需求与基础信息

根据用户的业务目标确定页面入口、输入、操作、产出与验证方式。只询问影响结果的缺失信息。已有工程先检查技术栈与当前工作区，保留用户修改；不要用空模板覆盖已有页面。

即用草稿在基础信息中使用 `template: "app"`。纯静态 H5 即用默认使用包内入口；HTML、CSS、JS、图片、字体与本地 JSON 数据都随包收集，无需启动 Node/Python/HTTP 服务。必须包含名称、稳定 key、SemVer 版本、用途、业务 instructions，以及 `ui.contributions`：

新即用和改进版本最低提供中文、英文双语。复用插件开发规范的 `locales` 展示配置：至少声明 `zh-CN`、`en-US` 的真实 `name`、`description`，页面入口用 `locales.<语言>.ui.<贡献id>.title/description`。公开参数和安装偏好也按同源规范翻译；用户要求韩语等时追加相应语言。只翻译展示文字，不修改 URL、参数值、权限、MCP 或执行指令。交付前验证中英切换、其他语言回退英文。业务页面按用户明确范围处理；仅翻译清单不能称页面已翻译。

```json
{
  "template": "app", "key": "example-app", "name": "示例即用", "version": "0.1.0",
  "description": "管理当前业务并通过 SoduWork 完成工作",
  "locales": {
    "zh-CN": {"name":"示例即用","description":"管理当前业务并通过 SoduWork 完成工作","ui":{"main":{"title":"示例即用"}}},
    "en-US": {"name":"Example App","description":"Manage work through SoduWork","ui":{"main":{"title":"Example App"}}}
  },
  "instructions": "根据用户要求完成当前即用的业务工作，读取真实记录、验证后写回并报告结果。",
  "inputs": [], "setup": {"preferences": []},
  "mcpServers": [], "runtimeCapabilities": [],
  "ui": {"contributions": [{
    "id": "main", "title": "示例即用", "slot": "workspace.navigation",
    "source": {"type": "package", "openMode": "workspace", "entry": "ui/index.html",
      "bridge": {"version": 1, "capabilities": ["conversation.send", "composer.control"]}}
  }]}
}
```

包内入口必须是 `ui/` 下实际存在的 HTML 相对路径，并在 `resources` 中以 kind `ui` 声明。全部运行依赖放在 `ui/`（kind `ui`）或 `assets/`（kind `asset`），使用相对路径，禁止 CDN 依赖，验证离线运行。壳通过内部资源协议读取安装包内容，各即用和账号的浏览器存储隔离，业务数据使用宿主 SQLite；localStorage/IndexedDB 仅存少量可丢弃的界面状态。页面无 Node.js、文件系统和任意 IPC 权限；使用随包 SDK 调用已声明的壳能力。安装只保存资源，点击即用才加载页面，不执行资源里的后端脚本。

## 即用专属彩色图标（必交付）

每个新建或改进的即用必须有与业务主题相符的精致彩色图标，品质参照 SoduWork 即用入口的彩色图形：主体清晰、色彩协调、适当层次、透明留白，在小尺寸下仍容易辨认。办公工具、小游戏、机器人等各有相符的视觉主体；不要用齿轮、拼图、加号、单色线框、emoji、首字母或宿主默认标代替专属设计。已有用户指定图标时保留它，不擅自换成模板标。

实际生成并检查 PNG，建议 128×128 或 256×256，尺寸不得超过 256×256、文件不得超过 96KB。将图片字节编码为 `data:image/png;base64,...`，写入草稿**顶层 `icon`**；只生成 `assets/icon.png` 而不填 `icon`，目录仍会显示默认占位图，不算完成。`icon` 不接受文件路径、远程 URL、SVG 或 emoji。若同时保留图片源文件用于页面或修改，放在 `assets/` 并以 kind `asset` 声明。

交付前查看 32px、48px 与正常尺寸，以及明暗背景下的边缘、留白和对比度；不能只检查图片文件存在。验证“检查并安装”后的目录、即用窗口及导出再导入都保留同一图标。随包 `validate.cjs` 拒绝缺少图标或格式不合规的最终草稿；脚手架仅是起点，完善专属图标并通过校验后才可交付。

已有在线业务服务继续使用 `source: {type:"external",url:"实际HTTP(S)地址",openMode:"workspace"}`。示例域名不能原样交付；该模式仍要求服务实际可用，不把作者电脑的127.0.0.1地址当作可分发服务。不能使用 file/data/javascript URL，不能把账号、密码、凭据放进 URL、草稿、提示词或导出包。

窗口默认 1800×1125 逻辑像素、居中、小屏自动适配；不要求用户配置尺寸。只有明确指定时才在根级声明 `appWindow`，详见基础规范。即用由独立窗口承载，主窗口切菜单保留它；多个即用各有独立页面与对话。页面中不要再实现壳的全屏、设置或对话面板。

## 页面、技能和对话

读取随本轮资源提供的 `sdk/README.md`，复制同目录 `sdk/soduwork-app.js` 到业务站点，使用公共函数，不能直接访问 Electron、原生 IPC 或设备身份。资源路径由开发助手运行时装配，SDK 始终来自客户端同一份源码。

- 自然语言自动匹配业务技能，不展示“选择技能”按钮。核心入口是一句业务意图；AI负责语义整理，编辑只保留用户确需修改的内容，避免管理表单。
- 意图提交先用 `soduWorkApp.chat.expand()` 展开右侧对话，再用 `soduWorkApp.chat.send({text, requestId})`。正文包含用户描述、真实业务 ID 和操作范围，由即用壳发送到当前即用的原生对话。
- 用 `soduWorkApp.createRequestId()`；同一次操作重试沿用同一个 ID，提交期间禁用重复操作。发送失败保留输入和已创建业务记录，允许单独补发；超时先核对对话，避免自动重复业务动作。
- 回执只证明会话已接收；真实业务完成需要模型执行、业务接口写回和读回证据。使用现有会话运行时与 MCP，不增加平行会话状态。
- 用 `soduWorkApp.events.onRefresh(callback)` 重新读取当前授权业务数据。壳负责刷新即用；刷新页面保留右侧对话及用户草稿。失败或取消后的刷新也不能被写成成功。
- 跨域 iframe 双方加载 SDK；顶层 `configure({allowedFrameOrigins:[精确来源]})`，直接子页面 `configure({parentOrigin:精确壳来源})`。走带来源和窗口校验的 postMessage，不能用通配符，不需要注册 URL 协议。任意深层 iframe 转发不在当前支持范围。
- 业务写回使用真实已配置连接器，或经用户认证的即用自有 MCP。沿用 SDK 和现有连接授权流程，不编造 MCP 名称、绕过 RBAC 或把凭据发送给模型。安装不能隐式执行资源脚本。

## 按需业务完成通知

即用自身的登录、ukey 和业务鉴权都是可选能力，不是安装、打开即用或使用对话桥的统一前提。允许纯本地、完全单机、无账号即用；不需要业务认证时，不生成登录页，不索取 ukey，不声明虚构 MCP 或凭据。示例中 `mcpServers: []` 与仅有对话桥权限的即用可以直接运行。SoduWork 自身的会话身份与即用业务账号分别处理，不能因为使用原生即用窗口就要求业务服务登录。

以下仅适用于用户明确需要业务登录或服务实际要求认证的即用。根据业务真实认证方式集成，ukey 只是字段示例，不是固定必填字段；不需要自动登录时也不必申请设置读写权限。

需要页面自动同步配置时声明 `settings.read`、`settings.write`，用 `soduWorkApp.settings.update({values,secretKeys,expectedRevision})` 写当前即用的参数；任意业务 JSON 参数都沿用此通路，不让用户复制到配置中心。ukey/令牌是敏感参数，系统安全存储保存，禁止放入即用包、提示词或会话正文。

需要自动登录时，页面登录成功后获取自身服务签发的凭据，再一次更新凭据和业务账号标识；退出只结束页面会话并暂停当前窗口自动登录，保留壳内凭据。例如使用 ukey 的服务，重开时通过 `settings.get({keys:['ukey'],includeSecrets:true})` 读取并向业务服务验证，再恢复登录。换号替换凭据，旧异步响应需核对当前账号和设置版本，不覆盖新账号。服务端撤销/禁用必须继续生效，不做两套用户体系的隐式合并。
需要业务完成通知时，可采用即用自有结果消息方案：页面发送前通过自身已认证接口登记稳定 requestId 和原业务范围；技能在实际写入并读回后用该即用 MCP 提交状态及结果引用。即用后端核对真实发起人、原请求、空间与结果，不接受模型指定其他接收人或仅凭文字宣称成功。页面在 onRefresh、重新加载或聚焦时读取自己的消息，重复事件按消息 ID 去重；收到 succeeded、partial、failed 或等待用户等真实回执后，才展示相应通知。发送受理或 onRefresh 只表示会话受理／轮次结束，回执缺失保持待确认。

消息正文的业务 type 和 JSON 内容由即用技能与前端共同定义；宿主不规定选题、视频等业务字段。消息按需关联结果记录，通知已读不代替审批或业务完成；用户点击后由前端的已支持处理器打开页面／弹窗，不执行消息中的任意 HTML/JS。换号、切空间和迟到响应必须隔离；需要离线恢复时消息及接收状态由业务服务持久保存。不需要业务通知的单机或无账号即用不强制建设后端或消息表。

当前公共 SDK 没有技能向业务页投递任意消息的 send_app_message/onMessage 通道，不得编造或假定支持。宿主通用投递属于后续方案，当前实现继续使用即用服务和现有轮次事件。验证重复回执、未知业务类型、失败／取消、缺失回执、刷新恢复及用户主动查看，不只验证成功提示。

## 机器人与即用内持续执行

“创建即用”中的机器人是以即用业务为中心、主要接入 SoduWork 自动化能力的即用，例如“灵感扭蛋机”“下班收尾官”“会议行动员”。它不是仅能对话的聊天机器人，也不是用定时器假装运行的静态页面。工具办公、小游戏和其他品类如有持续执行需求，也沿用同一条链路；无此需求不强加计划。

- **即用页面严禁出现“自动化”按钮。** 页面入口、表单、操作和状态全部使用适合当前业务的词语，例如简报里的“订阅简报”“发送时间”，桌面整理里的“定时整理”“整理范围”“下次整理”。不要只是把通用自动化面板改标题后塞进即用；内部接口、权限名和开发文档保留真实技术名称。
- 读取同源 `sdk/README.md`，在页面清单按需声明 `automation.create`，用 `soduWorkApp.automation.create({text, requestId, context})` 复用现有解析、能力绑定、时间校验、执行预检与 schedules API。不要自行实现后台轮询、页面 `setInterval`、系统计划任务或独立调度状态，也不要用聊天发送成功假装已建计划。不能编造 SDK 尚未提供的列表、暂停、删除接口；业务需要这些操作时先核对已有正式链路及授权，不用本地开关假装生效。
- 用自然语言收集意图，再以精简确认摘要明确执行时间、时区、频率、业务目标及操作范围，用户确认提交后才创建，不能点品类、进入页面或加载时直接保存。“下班前整理桌面”必须绑定真实目录、整理规则和具体时间，由已授权的真实技能执行；不能杜撰账号、目标或执行回执。不写时间时遵循 SDK 当前默认值并在提交前明示，不能暗藏默认安排。
- 使用稳定的真实业务空间上下文和同一次提交的 `requestId`，重试沿用编号；即用上下文不扩大授权，不复制即用凭据给计划。能力未声明、执行底座不可用或预检受阻时展示业务化失败信息，不退回自建调度器。`uncertain` 时先核对现有正式计划记录，不能换编号盲目重建。
- 保存成功仅显示“整理已安排”“每日汇报已安排”等真实状态；`schedule.id` 是已保存计划的关联编号，不是执行结果。每次触发在新建普通对话中执行，执行、失败和产出从现有对话/计划事实及业务回执读取，不另造任务或需求，不造倒计时、进度或成功记录。单机即用不因接入调度就自动变为云端即用，应说明当前执行端实际所需在线条件。

## 即用自定义参数与按需认证

参数、隐藏字段、安全存储、鉴权推荐与 MCP 显式绑定，见同目录 host-sdk.md；按实际业务选用。

## 生成、安装和交付

新即用可先运行无第三方依赖的 Node.js 18+ 脚手架，再完善实际业务：

```sh
node scripts/scaffold.cjs --out /work/new-candidate --key example-app --name "示例即用" --name-en "Example App" --entry ui/index.html
```

路径使用真实绝对路径，含空格时引用。out 必须是不存在的新目录；不填 `--url` 默认生成包内即用，脚手架生成草稿、可运行页面、同源 SDK 及成果清单。需要在线服务时再显式使用 `--url`；`serve.cjs` 仅供外部 URL 模式开发预览，包内静态即用不需要运行它。

在生成目录完善业务 instructions、核心操作和实际所需的业务技能/资源；资源逐项声明 path/kind。不需要的执行能力不添加。已有业务技能按现有 skills/MCP 契约复用，不复制成假接口。

`resources[].path` 相对于草稿所在目录，必须以 `templates/`、`examples/`、`assets/`、`scripts/`、`references/` 或 `ui/` 开头，并指向实际文件。例如页面 `ui/index.html`（kind `ui`）、图片 `assets/icon.png`（kind `asset`）、脚本 `scripts/server.cjs`（kind `script`）。不能把根目录的 `server.cjs`、`start.cmd`、`package.json`、`data/board.json` 或 `../` 路径直接列入资源，也不能只改清单而不移动文件及更新引用。作者预览服务和启动命令不是单机静态即用的安装依赖；单机即用使用包内入口与宿主 SQLite（浏览器存储仅少量可丢弃界面状态），不把临时 localhost 端口交给用户当可分发入口。确有在线服务需求时，服务部署与即用安装分别验证，安装不启动服务；宿主本地数据按 host-sdk.md 的声明式 JSON 执行初始化。

`resources[].kind` 只接受六个单数值：`template`、`example`、`asset`、`script`、`reference`、`ui`，对应上述六个目录。不能把复数目录名当成 kind，也没有 `icon` 类型。图标源文件可声明为 `{"path":"assets/icon.svg","kind":"asset"}`；SVG 可以作为随包图片资源，但不能直接作为草稿顶层 `icon`。顶层 `icon` 必须另填真实 PNG 的 `data:image/png;base64,...`，两处用途与校验规则不同。

**交付前必须执行只读校验，每次修复后重新执行：**

```sh
node scripts/validate.cjs --draft /work/new-candidate/soduwork-plugin-draft.json --work-root /work
```

使用本轮随包的真实脚本路径、实际草稿路径和当前会话目录。校验脚本复用安装器同源的路径、文件收集与草稿规范，拒绝根目录资源、越界/链接、缺失文件、校验不符和无效包内入口。失败先修复，再读取最终磁盘文件重新验证；退出码为 0 后才登记成果并提示“检查并安装”。校验不修改文件、不安装、不启动脚本，也不能证明页面或业务运行成功。不要用 `JSON.parse`、HTML 语法检查或开发预览正常代替这一步。

读取实际 JSON、检查全部文件，合并当前工作目录 `.soduwork/delivery.json` 的已有成果，唯一 primary 指向真实 `soduwork-plugin-draft.json`。清单必须使用 `{"schemaVersion":1,"deliverables":[{"path":"soduwork-plugin-draft.json","kind":"file","title":"即用草稿","primary":true}]}`，字段是 deliverables，不能写成 items。脚手架生成在子目录时，应把子目录内交付路径合并到当前会话的成果清单，不覆盖其他成果。不能声称安装会自动启动本地服务；只有真实服务已运行时页面才能打开。

使用本次回复旁的“检查并安装”：现有链路收集当前会话资源、预检并安装个人即用；不让用户去隐藏目录复制 JSON。需要分发时用原有导出入口生成 `.soduwork-plugin`，升版不覆盖旧版本。个人安装与企业审核/远端上架分别报告。

## 验证

严格阶段、启动诊断、失败修复与证据要求见 [development-workflow.md](development-workflow.md)。静态预检不能检出所有运行错误；原生打开与核心动作验收不可省略。

至少验证：草稿预检与资源完整；安装后出现在“即用→我的”；独立窗口打开真实页面；业务操作发送到该即用右侧会话；真实技能执行与业务读回；壳刷新后页面反映记录且对话保留；切主菜单窗口保留、多个即用不串会话；缺连接、重复点击、跨域未授权和发送失败处理；小屏与中英文。

按证据分别记录代码检查、隔离 Chromium/原生桥夹具、真实模型/真实业务实测和部署状态。测试夹具不能证明生产闭环，程序注入点击不能证明原生鼠标穿透。涉及图片/视频收费操作时遵循用户实际授权；没有条件的项目写明未实测，不能用静态成功替代。
